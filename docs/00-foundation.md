# DDD Foundation

**Type:** foundation
**Status:** accepted
**Source Issues:** #1 #4 #9 #19 #23

## Definition

Document Driven Development (DDD) is a development method in which unresolved questions are tracked as Issues, knowledge and decisions are fixed as Documents, implementation is derived as Change, and Tests/Evidence feed back into new Issues.

## Core idea

DDD is not documentation-first development. It is **knowledge-state-first development**.

The important question is not "where is the document?" but "what do we currently know, why do we believe it, what did we decide, and what verifies it?"

## Core cycle

`Issue → Evidence → Decision → Document → Change → Test → Feedback → Issue`

## Principles

1. Turn uncertainty into Issues.
2. Turn shared knowledge into Documents.
3. Record consequential decisions explicitly.
4. Derive implementation from accepted knowledge.
5. Treat Tests and Evidence as proof, not decoration.
6. Preserve superseded knowledge rather than erasing history.
7. Keep traceability bidirectional.
8. Use the method to develop the method itself.
