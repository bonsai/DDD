# Minimum Viable DDD

**Type:** operating-model
**Status:** accepted
**Source Issues:** #12 #22 #27

DDD does not require a large documentation bureaucracy.

## Minimum set

`Issue + Document + PR + Test`

- Issue: hold the question.
- Document: record the answer/knowledge.
- PR: propose the implementation.
- Test: verify the implementation.

PRD, RFC, ADR, Design, Research, Evidence, and operational documents are extension layers introduced when complexity or risk justifies them.

## Principle

Start with the smallest traceable loop and add document types only when a missing knowledge role becomes visible.
