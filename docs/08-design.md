# Design

**Type:** design
**Status:** accepted
**Source Issues:** #3 #19 #26

Design elaborates how an accepted requirement or decision will be realized.

## Canonical sections

- Context
- Requirements addressed
- Constraints
- Architecture / components
- Interfaces
- Data model
- Control flow
- Failure modes
- Security / performance considerations
- Migration
- Alternatives
- Related ADRs
- Verification strategy

Design should not silently introduce product-level decisions. New consequential choices become Issues/RFCs/ADRs.
