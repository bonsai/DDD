# PRD

**Type:** prd
**Status:** accepted
**Source Issues:** #3 #19

## Purpose

A PRD defines why a product or capability should exist and what outcome it is expected to create.

## Canonical sections

1. Problem
2. Target users / actors
3. Context
4. Goal
5. Non-goals
6. Value / success outcome
7. User stories / use cases
8. Requirements
9. Constraints
10. Acceptance criteria
11. Risks
12. Open questions
13. Related Issues

## Boundary

PRD answers **why and what outcome**. It does not decide implementation architecture. Architecture decisions belong in Design/ADR.

## Relationship

`Vision → Goal → PRD → Requirement → Issue`
